# gate1-inquiry-system
NEXUS55 Gate1 課題
Gate1 提出物
　社内問い合わせ管理システムの「ステータス変更・担当者割り当て機能」の実装

## 1. 起動手順
(環境構築コマンドと起動コマンドを書く)
1. GitHub Codespacesでリポジトリを開く
2. ターミナルを開く
3. 以下のコマンドで必要なライブラリをインストールする。
python -m pip install -r requirements.txt

4. 以下のコマンドでアプリケーションを起動する。
python app.py

5. Codespacesのポートから5000番ポートのurlを開く。
6. 問い合わせ一覧から「プリンタが印刷できません」をクリックすると詳細画面が表示される。

## 2. 動作確認手順
(どの画面でどう操作すると、何が起きるかを書く)
2.1 問い合わせ詳細画面の表示
1. 問い合わせ一覧を開く。
2. 「プリンタが印刷できません」をクリックする。
3. 問い合わせ詳細画面が表示されることを確認する。

2.2 正常なステータス変更
1. ステータスが「未対応」の問い合わせを開く。
2. 変更先に「対応中」のみが表示されることを確認する。
3. 「ステータスを変更」をクリックする。
4. ステータスが「対応中」になることを確認する。
5. 担当者が未割り当ての場合、操作したユーザーが自動的に担当者になることを確認する。
6. 変更履歴にステータス変更と担当者割り当てが記録されていることを確認する。

2.3 不正なステータス変更
1. ステータスが「未対応」の問い合わせを用意する。
2. テスト用の操作で「未対応」から「完了」への変更を送信する。
3. 次のエラーメッセージが表示されることを確認する。「このステータスへは変更できません。画面を再読み込みしてください。」
4. ステータスが「未対応」のままであることを確認する。

2.4 変更履歴
1. ステータス変更を実行する。
2. 問い合わせ詳細画面の「変更履歴」を確認する。
3. ステータスへんこうと担当者の自動割り当てが記録されていることを確認する。

## 3. 実装できなかった箇所
(できていない項目と、その理由)
・DONEからIN_PROGRESSへの再オープンと完了日時のクリア
・MEMBERとADMINの権限制御の全パターン
・無効ユーザーの選択制限
・同時更新時の競合チェック
・履歴登録失敗時のトランザクションのロールバック
実装コードに処理が含まれている場合でも、十分な動作確認ができなかったため。
